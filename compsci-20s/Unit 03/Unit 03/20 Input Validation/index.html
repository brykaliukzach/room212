Input Validation

When the user gives us a number, we have used the .Parse() method, because we're expecting them to give us a number (usually an int or double). But if they don't give us letters or something, our program crashes. This is no good.

TryParse

There's a better method called the .TryParse() method, but It's a little more complicated to use. Let's break down this new method piece by piece.

The simplest form of this new method is shown below.

int number;

int.TryParse(txb.Text, out number);

Here I am take the text from a textbox, and parse it to an integer. That part is simple. The new part is the out number If the user has actually entered a parsable integer, we send that value to the number variable. This is the simplest form of TryParse

But we can take it further...

What if we can't parse the number? Do we just ignore it and move on? Probably not a good idea. So let's combine this new way to parse with an if statement.

int number;

if (int.TryParse(txb.Text, out number))
{
    // We Parsed it! Continue writing code
}
else
{
    // We couldn't parse it, let the user know they messed up
}

Using if statements, we've created two blocks where we can write code. Now we can handle the situation where we can parse the number, and the situation where we can't parse the number. This way our program will always work, and always give some type of feedback

Take It Even Further

If your brain cannot handle a third and more advanced method, please continue to the next lesson. But for those who want another challenge - there's a third way that I like to use the TryParse

Instead of checking if I can parse the text, I'm going to check if I cannot parse the text

if (!int.TryParse(txb.Text, out number))
{
  
}

See that little ! exclamation at the start? That means a negation or the opposite. So instead of checking if I can parse, I'm checking the opposite - that I can't parse.

if (!int.TryParse(txb.Text, out number))
{
    // we couldn't parse, let the user know
    return;
}


// rest of block code down here

So at the start of my block, I check if the user did not give me parsable number. If I can't parse their number, I let them know, and I stop the rest of my code from running with the return command.

return stops any code from running after it. If the user gives me parsable input, the if statement condition is never met, and therefore the return command is never executed, so the rest of the code proceeds as normal.

If they don't give me parsable input, the if statement condition is met, and we go inside, and eventually stop the outside code from executing with the return command.

Key Takeaways

  • .TryParse() prevents my programs from crashing
  • Pair .TryParse() with an if statement for simple input validation
  • return command stops all code below it from executing
